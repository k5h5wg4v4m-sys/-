# TABYLGA: правила проекта для Claude Code

Маркетплейс объявлений Кыргызстана. Полное ТЗ: `SPEC.md`. База данных: `supabase/migrations/`.
Валюта: сом (KGS). Языки интерфейса: русский и кыргызский (полностью, через i18n, без хардкода текста).

## Стек
Next.js (App Router), TypeScript, Tailwind CSS, Supabase (PostgreSQL, Auth, Storage, Realtime).
Позже: Capacitor для Android/iOS, Firebase Cloud Messaging для push.

## Как работать
- Делай ТОЛЬКО тот этап, который я назвал. Не забегай вперёд.
- Перед началом этапа кратко напиши план (5-10 строк). После этапа: `npm run lint`, `npm run build`, проверь работу вручную по сценарию и расскажи, что проверено и что нет.
- Один этап = один git-коммит с понятным сообщением.
- Все кнопки должны выполнять реальные действия. Никаких фейковых данных и заглушек вместо базы.
- Если чего-то не хватает (ключ, аккаунт, решение), остановись и спроси, не придумывай.

## Деньги и безопасность (самое важное)
- Баланс, статус пользователя, роли, цены и сроки меняются ТОЛЬКО через SQL-функции в базе (`create_listing`, `relist_listing`, `moderate_listing`, `review_topup`, `admin_adjust_balance`, `admin_set_block`, `delete_listing` и др.). Клиент вызывает их через `supabase.rpc`.
- Никогда не доверяй суммам, статусам, ролям и срокам, пришедшим с клиента. Не считай деньги в браузере иначе как для показа.
- Ключ `service_role` используется только в серверном коде (route handlers, Edge Functions) и никогда не попадает в клиентский бандл. В клиенте только `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
- Секреты только в `.env.local`. Он в `.gitignore`. Веди `.env.example` без значений. Не печатай ключи в логах и ответах.
- RLS включён на всех таблицах. Любая новая таблица: сразу RLS и политики.
- Любые изменения базы только через новые файлы миграций `supabase/migrations/NNN_name.sql`. Старые миграции не переписывай.
- Не делай автоматическое зачисление денег по чеку: только одобрение администратором.
- Роль `moderator` не может менять балансы и одобрять пополнения. Для денежных операций проверяй роль `admin` (создай функцию `is_super_admin()`).

## Ошибки базы
Функции возвращают коды ошибок в сообщении: `insufficient_funds`, `account_blocked`, `profile_incomplete`, `bad_days`, `bad_title`, `bad_phone`, `bad_region`, `bad_price`, `bad_images`, `bad_image`, `bad_status`, `not_found`, `forbidden`, `reason_required`, `already_reviewed`, `listing_not_available`, `own_listing`, `proof_required`, `bad_amount`, `bad_method`. Покажи пользователю понятный перевод (ru и ky) для каждого, а не сырой текст.

## Форматы
- Телефон: Кыргызстан +996 и 9 цифр. В Supabase Auth номер хранится без плюса.
- Цена: `1 200 сом`, разделитель тысяч пробел.
- Даты показывай в часовом поясе Бишкека (Asia/Bishkek), срок объявления считает сервер.
- Фото: сжимай в браузере перед загрузкой (до ~1600 px по длинной стороне, JPEG/WebP до ~500 КБ), путь файла `<user_id>/<uuid>.<ext>`.

## Интерфейс
Премиальный маркетплейс, светлая и тёмная тема, закруглённые углы, мягкие тени, плавные анимации. Мобильная версия в первую очередь: фиксированное нижнее меню из 5 пунктов (Главная, Избранное, +, Чаты, Профиль). На компьютере адаптивная боковая или верхняя навигация. Состояния загрузки, пустые состояния и ошибки на каждом экране.
