# База данных TABYLGA (Supabase)

## Миграции

| Файл | Что внутри |
|---|---|
| `001_base.sql` | Профили, роли персонала (`admins`), категории (20), регионы (9), уведомления, журнал модерации, блокировка (`admin_set_block`) |
| `002_finance.sql` | Транзакции (финансовый журнал), способы оплаты (7 банков), заявки на пополнение, `review_topup`, `admin_adjust_balance` |
| `003_listings.sql` | Объявления, фото, избранное, жалобы, `create_listing`, `relist_listing`, `moderate_listing`, `delete_listing`, `expire_listings`, `search_listings` |
| `004_chat.sql` | Чаты, участники, сообщения, поддержка, `start_chat`, `send_message`, `get_my_chats`, `send_support_message` |
| `005_storage.sql` | Бакеты Storage с лимитами размера и типов, доступ только к своей папке |
| `006_jobs.sql` | Автозавершение объявлений каждые 5 минут (pg_cron), Realtime |

Таблица пользователей — `auth.users` (Supabase Auth, пароли хранятся как bcrypt-хеш). Остальные таблицы из ТЗ — в `public`.

## Как применить к проекту Supabase

**Вариант A — SQL Editor (без установки программ).**
1. Supabase → Database → Extensions: включите `pg_cron` (до шага 2).
2. SQL Editor → вставьте и выполните файлы `001` … `006` строго по порядку.

**Вариант B — Supabase CLI.**
```bash
npx supabase login
npx supabase link --project-ref <ref проекта>
npx supabase db push
```

## Первый администратор

1. Зарегистрируйтесь на сайте по номеру телефона.
2. В SQL Editor выполните (номер без плюса):
```sql
insert into public.admins (user_id, role)
select id, 'admin' from public.profiles where phone = '996XXXXXXXXX';
```
Роль `moderator` (объявления, жалобы, поддержка — без денег): то же самое с `'moderator'`.
Назначать роли можно только через SQL Editor / service role — из приложения это невозможно.

## Правила, которые держит база

- Баланс меняется только функцией `_apply_balance_change`: блокировка строки, запрет минуса, запись в журнал «было → стало, кто, почему». Даже прямой `update` под service role отклоняется.
- Одна заявка — одно зачисление (уникальный индекс), одно списание и один возврат на оплаченный период объявления.
- Повторная отправка формы объявления с тем же `client_request_id` не создаёт дубль и не списывает деньги.
- Срок объявления отсчитывается от одобрения модератором по времени сервера. Истёкшие объявления скрыты сразу (RLS проверяет `expires_at > now()`), планировщик лишь меняет статус и шлёт уведомления.
- Возвраты: отклонено на модерации — 100 %; отклонено активное — за неиспользованные полные дни; удалено владельцем до модерации — 100 %; удалено владельцем после публикации или персоналом за нарушение — без возврата.
- `moderator` не видит финансы и не может менять балансы, одобрять пополнения, блокировать и править реквизиты. Личную переписку пользователей персонал не читает.
- Заблокированный пользователь не может публиковать и писать продавцам, но может писать в поддержку.
